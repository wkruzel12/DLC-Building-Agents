# Guided scenario briefing and case materials

Scenario Briefing remains on `/scenario` and has three freely accessible tabs: Understand Your Scenario, Explore Your Materials, and Understand Your Mission. Tab selection and viewed activities are saved per browser/account and case using the existing localStorage/sessionStorage convention. Tabs support arrow keys, Home, End, Enter, and Space with explicit tab/panel relationships.

Context and assignment introductions use short excerpts of the original case wording, not generated summaries or invented business facts. Longer text can be expanded without losing its complete source. The mission explains Extract, Check, and Flag, preserves the provided requirements, allowed actions, and skill tags, and links to the existing builder. Students are not required to open every document or complete a new gate.

`case-materials.ts` constructs a library only from explicitly public context, task, requirements, and every record's exact label, identifier, and text. It does not enumerate arbitrary case metadata or inspect grading fields. Materials are classified by their actual role in the case, without assuming recruiting terminology. Search covers titles, original record IDs, and full text; type filtering uses only categories present in the selected case. Empty searches and missing text have explicit messages.

`CaseMaterials.tsx` is shared by the briefing library and the builder's View Case Materials drawer. Document cards open a full-text reader in place and restore focus to the document button on closing. Reader text is rendered as escaped React text, with keyboard-accessible scrolling. The modal drawer uses the native dialog focus boundary, explicit Escape/cancel handling, a Close button, and focus restoration to its trigger. It remains usable on narrow screens and does not navigate away from the active builder stage or change instructions, tests, scores, or history.

Search, filters, and the open document ID are saved separately for briefing and builder references, scoped by case and identity. Original record IDs are displayed unchanged; internal document keys are separate to avoid collisions with section names.

No new database, authentication rule, upload schema, model call, or storage service is needed. Materials show the complete validated text already available in `PublicScenario`. Existing uploads do not retain original PDF/JSON attachments as downloadable documents, so this feature does not claim to display original file layouts or recover attachments absent from case data. Existing case ownership and redaction APIs continue to control access.

Verification: `npm test`, `npx tsc --noEmit`, and `npm run build`. `node tests/briefing-journey.cjs` uses an isolated Edge profile to check sample and uploaded non-hiring cases, all tabs, full text, search/filtering, privacy, state restoration, desktop/mobile layouts, and keyboard focus. It also makes three real isolated OpenAI stage tests to verify reference access preserves all three working stages and prompts; it creates no full simulation attempts. Screenshots remain in ignored `.test-artifacts/`. The existing `tests/local-journey.cjs` entry flow has been updated for the new briefing navigation.
