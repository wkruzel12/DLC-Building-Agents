# Guided scenario briefing and case materials

Scenario Briefing remains on `/scenario` and has three freely accessible tabs: Understand Your Scenario, Explore Your Materials, and Understand Your Mission. Tab selection and viewed activities are saved per browser/account and case using the existing localStorage/sessionStorage convention. Tabs support arrow keys, Home, End, Enter, and Space with explicit tab/panel relationships.

What's Happening contains exactly three content sections: Context, Objective, and Evaluation Criteria. They show the complete original wording without generated summaries. Criteria use a numbered list with wrapped details kept together. The presentation-only `case-briefing.ts` projection reads the public story/task/requirements fields and recognizes explicit section headings in combined-document imports. Record sections and repeated complete record text are excluded from the introduction; the original public fields and every record remain unchanged in the existing materials library. Missing content has an explicit message rather than invented facts.

The mission explains Extract, Check, and Flag, preserves the provided assignment, requirements, allowed actions, and skill tags, and links to the existing builder. The previous introductory role and AI explanations now live in optional mission details; the original workflow learning note accompanies the assignment. Students are not required to open every document or complete a new gate.

`case-materials.ts` constructs a library only from explicitly public context, task, requirements, and every record's exact label, identifier, and text. It does not enumerate arbitrary case metadata or inspect grading fields. Materials are classified by their actual role in the case, without assuming recruiting terminology. Search covers titles, original record IDs, and full text; type filtering uses only categories present in the selected case. Empty searches and missing text have explicit messages.

`CaseMaterials.tsx` is shared by the briefing library and the builder's View Case Materials drawer. Document cards open a full-text reader in place and restore focus to the document button on closing. Reader text is rendered as escaped React text, with keyboard-accessible scrolling. The modal drawer uses the native dialog focus boundary, explicit Escape/cancel handling, a Close button, and focus restoration to its trigger. It remains usable on narrow screens and does not navigate away from the active builder stage or change instructions, tests, scores, or history.

Search, filters, and the open document ID are saved separately for briefing and builder references, scoped by case and identity. Original record IDs are displayed unchanged; internal document keys are separate to avoid collisions with section names.

No new database, authentication rule, upload schema, model call, or storage service is needed. Materials show the complete validated text already available in `PublicScenario`. Existing uploads do not retain original PDF/JSON attachments as downloadable documents, so this feature does not claim to display original file layouts or recover attachments absent from case data. Existing case ownership and redaction APIs continue to control access.

Verification: `npm test`, `npx tsc --noEmit`, and `npm run build`. `node tests/briefing-journey.cjs` uses an isolated Edge profile to check sample and uploaded non-hiring cases, all tabs, full text, search/filtering, privacy, state restoration, desktop/mobile layouts, and keyboard focus. It also checks that the combined builder keeps all three authored fields intact when the materials drawer opens and closes; it makes no model calls or full simulation attempts. Screenshots remain in ignored `.test-artifacts/`. The existing `tests/local-journey.cjs` entry flow has been updated for the new briefing navigation.

The browser check also uploads a synthetic ten-applicant fixture containing a combined story. It checks the three introductory sections against exact source strings, opens and compares all ten original records, checks privacy and the mission, and reloads the saved material selection. Set `LAB_TEST_BRIEFING_ONLY=1` to stop before the builder drawer/draft checks. `tests/case-briefing.test.cjs` covers the same projection for separate and combined fields, numbered/inline headings, punctuation, multiline criteria, missing content, and non-hiring cases. The built-in sample contains five records; its original record count is preserved.

## Presentation update

The five main navigation labels remain unchanged. Scenario Briefing retains all three internal tabs and their original keyboard/state behavior. A shared current-objective strip and compact tab styling organize the page. Long educational explanations are available through native details controls; source summaries always retain access to the complete original text. View Full Case opens the same public reference library in a dialog without leaving the selected activity. The new preservation inventory is in `docs/ui-preservation-inventory.md`.
